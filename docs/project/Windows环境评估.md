# Windows 环境可行性评估
2026-11-04｜供解决方案选型使用，非安装完成记录

## 结论
优先评估 WSL2 + Ubuntu：无需双系统分区，适合运行原项目的 Linux 工作流。若本机不允许虚拟化或没有管理员权限，可考虑远程 Linux；Windows 原生可试，但尚未验证该项目的完整兼容性。无需为了本项目先购买 GPU。

尚未检查本机 Windows 版本、内存、磁盘、管理员权限、虚拟化设置和组织策略，因此以下是条件性估算，不是对本机安装成功的保证。

| 路线 | 首次准备成本估算 | 资金及资源 | 适用性 |
|---|---|---|---|
| WSL2 + Ubuntu | 顺利时 1–3h 建立系统和基础工具；加项目旧依赖通常共 3–8h，故障排查可能更久 | WSL/Ubuntu 无额外软件购买成本；建议本机 16GB RAM，Linux 工作负载先分配约 4–8GB；系统/依赖预留 10–20GB，数据另计 | 首选；需管理员权限、硬件虚拟化及重启条件 |
| Windows 原生隔离 Python 环境 | 可先用 1–2h 检查安装、导入和冒烟运行；完整移植可能 4–12h 以上 | 通常无新增软件费用；可能需编译工具 | 不安装 Linux；旧依赖、路径及脚本需逐项验证，不能假设可直接复现 |
| 已有远程 Linux / 租用 CPU 主机 | 已有主机约 1–3h 接入，另加数据传输和项目依赖准备 | 已有机器可能无新增费用；租用按 CPU、磁盘、时长、流量计费 | 无法修改本机系统时优先；先确认数据许可和存储权限 |
| 完整 Linux 虚拟机 | 系统准备约 2–5h，另加依赖准备 | 额外系统镜像和虚拟磁盘；内存占用较高 | 可用但通常比 WSL2 更繁琐，同样依赖虚拟化 |
| 双系统 | 约 4–8h 以上，取决于备份、分区和驱动 | 需要独立磁盘空间及维护 | 对本项目投入较大，不建议作为第一选择 |

上述工时和资源均为工程经验估算，不是官方承诺；网络下载和学习 Linux 的时间单独计算。数据需额外数十 GB，压缩包、解压和多份副本可能翻倍；应按实际清单计算容量。云服务未选择供应商，故不编造具体报价：总费用=实例小时价×运行时长+磁盘+网络费用；60小时人工投入不等于60小时租用时长。

## WSL2 安装条件及实际影响
微软的简化安装命令要求 Windows 10 2004（build 19041）及以上或 Windows 11；管理员 PowerShell 执行 `wsl --install` 后按提示重启。还需确认硬件虚拟化开启及设备策略允许。安装会添加 Windows 功能与 Linux 发行版，不需要将 Windows 替换为 Linux。[微软安装说明](https://learn.microsoft.com/en-us/windows/wsl/install)、[手动安装及虚拟化条件](https://learn.microsoft.com/en-us/windows/wsl/install-manual)。

项目依赖应安装在 Linux 自己的 Python 环境中，不复用 Windows 的虚拟环境。实验项目及大量小文件优先放在 Linux 文件系统内，Windows 侧保存交付文档和必要同步副本；额外副本计入存储。[微软文件系统建议](https://learn.microsoft.com/en-us/windows/wsl/filesystems)。Docker Desktop 的 Linux 容器通常仍需要虚拟化后端，因此不能简单视为绕过 Linux 环境条件的方案。

## 决策检查点
先只读检查系统版本、RAM、可用空间、虚拟化及权限；符合条件后再决定是否安装 WSL2。系统安装与重启另行执行，本次仅交付评估。项目环境选型完成的证据必须是：锁定版本的依赖可导入、单序列跟踪完成、官方评测运行成功。操作系统装好本身不足以证明可复现。
