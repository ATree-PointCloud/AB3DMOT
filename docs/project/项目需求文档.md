# KITTI + AB3DMOT：3D 多目标跟踪基线复现与关联鲁棒性改进

项目需求文档 v1.2｜2026-11-12｜投入约束：约 60 小时，具体安排另见解决方案

实施状态以 [当前状态与下一步.md](当前状态与下一步.md) 为准。当前采用直接 fork 布局，从本地解释器配置开始，环境、输入、跟踪和评测均待验证；本文中的验收标准保持不变。

## 1. Overview · 项目背景
自动驾驶跟踪需要将连续帧中的三维检测框关联为稳定轨迹。检测抖动、短时漏检与目标交汇会造成轨迹碎片和身份切换。本项目采用 tracking-by-detection 路线，固定官方 AB3DMOT 仓库提供的 PointRCNN 检测输入，复现公开基线，再研究一种关联改进。重点展示数据协议理解、可复现工程、受控实验和诚实的结果分析，而非训练检测器或追求排行榜成绩。

KITTI tracking 含 21 个公开标注训练序列和 29 个隐藏标签测试序列。KITTI 当前官方排行榜评价的是二维框跟踪，主要排名指标为 HOTA；AB3DMOT 提供本地三维评测扩展。二者结果必须分开呈现。[S1–S3]

## 2. Objective · 目标与成功定义
1. 在锁定代码版本、输入和评测器后完成官方验证集基线复现。
2. 主研究对象为 Car；官方三类别汇总作为复现检查，时间不足时优先完成 Car，明确标注缩减范围。
3. 基于基线错误分析和开发集实验探索，确定并实现至少一种有效的关联鲁棒性改进；需求不预设算法、公式或参数。最终以一种经验证的方案为主线，保留探索记录。
4. 用固定检测输入、相同随机种子和相同评测协议比较干净输入及噪声、连续漏检条件下的性能。
5. 无性能提升时项目尚未完成：必须分析原因、修正假设并探索新方案，直至满足改进验收要求。负结果是迭代证据，不能替代有效改进。若约 60 小时内未达标，应记录为未完成并评估后续投入，不得降低标准或虚构结论。

## 3. Rules · 范围和排除项
必须：基线运行、格式检查、单一改进、成对实验、逐序列分析、复现说明、结果表和失败案例。
不包含：PointRCNN 训练或重新推理、端到端学习、外观 ReID、多个跟踪器竞赛、在线部署、真实车辆安全验证、官方隐藏测试集提交。点云渲染、其他类别改进及 HOTA 为可选项，不得挤占主实验预算。

[S2] [AB3DMOT 官方仓库](https://github.com/xinshuoweng/AB3DMOT)：代码、配置、检测文件和依赖说明。使用其 data/KITTI/detection 下的 PointRCNN 输入；这不是 KITTI 官方提供的检测结果，也不是 GT。
[S3] [官方 KITTI 运行和复现说明](https://github.com/xinshuoweng/AB3DMOT/blob/master/docs/KITTI.md)。
[S4] [数据划分和初始化代码](https://github.com/xinshuoweng/AB3DMOT/blob/master/AB3DMOT_libs/utils.py)。
[S5] [检测读取和结果写出代码](https://github.com/xinshuoweng/AB3DMOT/blob/master/AB3DMOT_libs/io.py)。
[S6] [论文](https://arxiv.org/abs/2008.08063)。论文版本与当前仓库的改进版本不能直接混用。
[S7] [TrackEval 官方仓库](https://github.com/JonathonLuiten/TrackEval)：可选二维评测。

KITTI 与 AB3DMOT 来源核对于 2026-11-03；环境补充核对于 2026-11-04。实施第一步保存具体 commit SHA、配置和文档快照；master 是移动引用，不能作为最终版本标识。下载后记录文件清单、字节数及 SHA-256。检测文件缺失或下载链接失效时停止性能对比，不得以其他检测器输入替代后仍宣称复现同一基线。

### 4.1 数据布局
仓库文档给出 data/KITTI/tracking/training/{calib,image_02,label_02,oxts,velodyne}。但 utils.py 的初始化路径也可能直接从 data/KITTI/training 读取：必须以锁定版本实际调用路径为准，通过配置、目录联接或薄适配器解决并记录。不要默默维护两份数据。

跟踪器使用预计算检测，不需要为了检测训练下载点云；但当前初始化可能依赖图像帧清单、OXTS 与标定，即使不制作视频也需检查。点云只为可选可视化下载。先下载必要文件和一个验证序列进行冒烟运行，再批量准备。预留至少数十 GB 存储；实际空间按下载包和解压文件计算。

### 4.2 检测输入 schema
每序列一个逗号分隔文件，N×15；列号以下均从 0 开始：

| 列 | 字段 | 类型 / 单位 |
|---|---|---|
| 0 | frame | 整数，0 起始 |
| 1 | type | 1=Pedestrian，2=Car，3=Cyclist |
| 2–5 | left,top,right,bottom | 像素，图像坐标 |
| 6 | score | 检测器原始分数，不保证为概率 |
| 7–9 | h,w,l | 米，严格保留次序 |
| 10–12 | x,y,z | 米，相机坐标中的框底面中心 |
| 13 | rotation_y | 弧度，绕相机 y 轴 |
| 14 | alpha | 弧度，观察角 |

示例：0,2,726.4,173.69,917.5,315.1,13.85,1.56,1.58,3.48,2.57,1.57,9.72,-1.56,-1.82。此为官方说明中的格式示例，不作为测试数据或验收结果。[S3,S5]

GT 为 KITTI 空格分隔 tracking 标签：frame track_id type truncated occluded alpha bbox_left bbox_top bbox_right bbox_bottom h w l x y z rotation_y；结果追加 score，形成 18 列。保留 DontCare 和类别处理规则，交给固定评测器处理。track_id 在序列内唯一；不得跨序列关联。评测输入用 data_0，不能误用面向可视化的 trk_withid_0。

### 4.3 坐标与质量约束
整流相机坐标：x 向右、y 向下、z 向前；KITTI 的位置是底面中心，几何中心需 y−h/2。Velodyne 通常 x 向前、y 向左、z 向上，必须通过标定变换到相机坐标，不能直接混用。alpha 与 rotation_y 含义不同，角度差采用 wrap 至 [−π,π)。内部状态的维度顺序以锁定实现为准，必须显式映射。

检查：15 列、有限数值、正尺寸、合法类别、帧范围、框边界顺序、序列覆盖与空帧；空帧仍执行预测/老化，不得跳过。单行和空文件要有处理。标签无效值按官方评测器解释，不得自行筛选以提高得分。标定、图像、OXTS 与检测的帧索引必须一致。

## 5. Split · 划分及防泄漏
沿用 AB3DMOT 的序列级划分 [S4]：
- 开发池：0000,0002,0003,0004,0005,0007,0009,0011,0017,0020。
- 官方复现验证集：0001,0006,0008,0010,0012,0013,0014,0015,0016,0018,0019。

实现注意：utils.py 虽列出 train 序列，但某些版本对 split=train 的前置分支会报错；开发运行需显式序列清单适配，不得直接假设命令支持 train。先检查官方检测文件是否覆盖开发池。若不覆盖，不以验证集反复调参：预先从验证集划出开发子集并锁定，剩余为内部留出集；此时官方全验证结果只能称复现/描述性比较，不称完全独立检验。

参数只在开发池或预声明的开发子集选定。禁止随机逐帧划分、用未来帧关联、读取 GT 构造改进代价、看留出结果后挑噪声强度。GT 仅用于离线评测和诊断；合成遮挡需使用检测构造的固定代理轨迹，不用 GT ID 决定主实验删框。官方原系统本身可能曾用验证集选择阈值，需披露继承这一历史限制，不能声称整个基线从未见过验证集。检测器训练数据来源若无法核实，明确标为未知风险。

## 6. Evaluation · 评测协议
### P1：AB3DMOT 本地 3D 主协议
固定官方评测代码、GT、序列列表、类别和过滤配置；主阈值 3D IoU=0.25，补充 0.5，Car 0.7 只作诊断。sAMOTA 越高越好，为评测器按召回率采样与归一化得到的汇总指标；不能用单一分数阈值的 MOTA 代替。MOTA=1−(FN+FP+IDS)/GT，可为负；IDS 是该评测器规则下的身份切换数。所有指标都记录尺度（百分数或比例）、阈值和分数扫描/工作点。

报告 sAMOTA、MOTA、IDS，并补充 FP、FN、FRAG、逐序列结果与跟踪耗时。MOTA/IDS 是否来自评测器选择的最佳工作点必须从锁定代码确认并标注；额外鲁棒性比较采用开发集冻结的分数工作点，避免每个扰动条件重新选择最优阈值。官方复现保持原始扫描行为。三类汇总仅依照官方规则，不以逐序列指标简单平均代替官方聚合。

公开参考：官方 KITTI.md 的 PointRCNN+AB3DMOT、val、3D IoU 0.25 表中，Car sAMOTA=93.34%、MOTA=86.47%、IDS=0。[S3] 这些是公开参考值，不是本项目已经测得的结果。该页面注明当前代码优于原始论文版本。必须匹配版本和输入后才可逐项比较；复现默认容差为百分数指标绝对差≤0.1 个百分点、整数计数一致，超差给出原因并标为未通过，不能通过放宽容差掩盖问题。FPS 不要求等同论文机器。

### P2：可选 KITTI / TrackEval 二维协议
采用独立锁定的 TrackEval KITTI 配置、二维 bbox IoU、官方过滤与 HOTA 阈值扫描，报告 HOTA、DetA、AssA 和 CLEAR 指标。明确类别、图像框来源、单一分数工作点和序列范围。它衡量二维投影跟踪，不是 P1 的三维 sAMOTA，也不与 P1 的 MOTA/IDS 混表排名。本地 val 分数不是官方 test 排行榜成绩。若修改为三维 HOTA，必须另命名为自定义研究协议，60h 内不要求实现。

## 7. Baseline · 复现与环境
当前采用本地 Windows 编辑、远程 AutoDL Linux 验证；《Windows环境评估.md》保留为早期选型记录。CPU 可运行预计算检测跟踪；GPU 不作为必要依赖。主机、CPU、内存、系统、Python 及安装方式写入环境记录。依据锁定仓库的导入链逐项验证实际依赖；当前 requirements.txt 保留上游旧依赖，requirements-project.txt 记录待验证的候选直接依赖，不直接批量安装旧版本。最终保存 pip freeze 和辅助库 SHA，不能只交一份未验证的宽松版本列表。旧依赖兼容修改单独提交，不改变关联逻辑。安装不明依赖前核实来源。

流程：克隆官方仓库→锁定 SHA→准备数据→运行单序列/少量帧→全部验证集→运行评测。官方命令模板（在官方仓库根目录执行）：

```bash
python main.py --dataset KITTI --det_name pointrcnn
python scripts/KITTI/evaluate.py pointrcnn_val_H1 1 3D 0.25
python scripts/KITTI/evaluate.py pointrcnn_val_H1 1 3D 0.5
python scripts/KITTI/evaluate.py pointrcnn_Car_val_H1 1 3D 0.7
```

名称与输出路径以锁定版本为准。保留未修改配置和完整日志。先阅读该版本关联算法、代价（可能为 GIoU）、阈值、max_age、min_hits、运动补偿等实现，不把论文早期的 IoU/Hungarian 概述当作当前配置事实。基线重复运行一次检查结果文本和指标稳定性。计时注明是否包含文件读取、可视化与评测，检测时间单独排除并披露。

## 8. Improvement · 探索与改进要求
首先在开发集分析基线的错误类型、发生条件、逐序列差异及关联失败案例，据此提出可检验的假设。具体方案、候选比较、参数范围和实现设计写入独立解决方案，不在需求中指定。

每轮实验记录假设、改变因素、对照、结果、解释和下一步；未提升时区分实现问题、评测问题、假设不成立与适用条件不足，再探索新的方案。最终通过消融证明提升来自所提出的改进。固定检测器、输入和主评测协议；最终方案应可关闭，关闭后恢复基线行为。不得靠改变数据过滤、评测阈值或挑选有利序列获得表面提升。

候选选择和失败后的迭代均在开发集进行。方案和参数冻结后才进行最终留出评测；若根据留出结果重新设计，原留出集已成为开发证据，必须披露并重新建立独立验证机制，不能反复使用后仍宣称独立验证。

## 9. Robustness · 受控实验
预先冻结条件：clean；位置噪声 σ=0.1/0.3/0.5m（相机 x,z 独立零均值高斯，y、尺寸、朝向、分数不变）；独立随机删框 p=0.1/0.3；连续漏检长度 L=2/4/6 帧。每种条件单独施加，主实验不做全因子组合。随机种子固定为 17、42、2026；clean 只需一次确定性结果。

连续漏检：对原始检测使用固定的离线几何代理轨迹和预先固定采样率（每条长度≥12帧轨迹最多一个片段，20%轨迹抽样），生成删除行号清单；生成器独立于待比较跟踪器，不读取 GT。代理关联误差需披露；本实验模拟检测缺失，不等同真实物理遮挡。预算不足时采用序列内固定时间窗口删除 Car 检测作为退化方案，并明确这是群体缺失实验。

每一扰动文件只生成一次，baseline/improved 共用文件哈希。GT 不变；只扰动输入而非标签；不添加负深度或无效数值。若研究原始 GT occluded 子集只用于事后诊断，不能用于选择参数。保存实际删除率、片段数、噪声统计及原始行号映射。

结果矩阵：2 个方法×(clean 1次 + 8个扰动等级×3种子)=50 次全验证运行；若三类复现较慢，扰动仅跑 Car。每个条件汇报成对差值、均值/标准差及逐序列分布，不把三个随机种子当作独立场景样本宣称统计显著。主鲁棒性结果为预声明 8 个扰动等级的平均 sAMOTA 差，等级等权且先对种子平均；同时展示全部条件，避免只挑有利结果。IDS 基线为零时给绝对差，不计算无意义的下降百分比。

## 10. Reproducibility · 可复现要求
每次运行产生 run_id、UTC 时间、代码 SHA/dirty diff、依赖锁定、输入 SHA-256、split 清单、配置、种子、命令、stdout/stderr、耗时和原始评测输出。结果文件禁止覆盖；生成汇总表必须从原始日志读取。提供一条入口依次执行数据检查、跟踪、评测和汇总，失败时非零退出。未实现的命令必须标为计划，不伪装成可执行功能。

结果表字段：run_id,protocol,commit,method,split,class,iou,condition,level,seed,score_policy,sAMOTA,MOTA,IDS,FP,FN,FRAG,runtime_sec,input_hash。不同协议独立表。图表至少包含扰动强度曲线、逐序列差值和两组含身份标记的失败案例。记录随机噪声复用方式，Python hash 随机化不得影响采样顺序。

## 11. Submission · 交付和验收
必须交付：本需求文档、README、来源/环境/输入清单、固定 split 和配置、原始基线输出、关联补丁、扰动清单、实验原始日志、结果 CSV、曲线、失败案例及最终报告。数据本体不入 Git。

工程验收：从说明可重建环境；数据检查失败会终止；同一输入配置可重复得到同一指标；关闭改进后等价基线；成对实验输入一致；运行记录完整。
科学验收：基线满足前述容差或明确判为未复现并解释；全部预声明条件完整披露；开发和留出集分离；P1/P2 分开；参考值和实测值分开。性能目标是 clean sAMOTA 下降≤0.5个百分点，扰动平均 sAMOTA 提升≥0.5个百分点，且同步分析 MOTA/IDS/FP/FN；以上为性能验收条件；需在未参与方案选择的留出数据上验证，并完成消融及逐序列分析。不达标时只可交付阶段成果，项目状态仍为未完成，继续分析原因和探索新方案。基线未复现也不能通过完整项目验收。

## 12. 项目结构与开始步骤
